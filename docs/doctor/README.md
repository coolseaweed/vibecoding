# 세션 Doctor

이 문서는 에이전트가 현재 바이브코딩 세션을 자가진단하고 개선할 때 사용하는 단일 기준(SSOT)입니다.

현재 저장소의 `AGENTS.md`, 사용자 요청, GitHub Issue 또는 `Plan.md` 순서로 Goal을 찾습니다.

## 중단 조건

Goal, 작업 범위, 완료 기준 중 하나라도 없으면 `BLOCKED`입니다. 에이전트는 추측해서 구현하지 않습니다.

배포, 비밀값, DB 쓰기, 삭제가 필요하면 사용자 승인 전에는 실행하지 않습니다.

## 1. 환경셋업

- [ ] 프로젝트에 필요한 CLI, 계정 인증, 의존성 설치가 정상입니다.
- [ ] 저장소의 검사 명령이 모두 통과합니다.
- [ ] Goal에서 Vercel 또는 Supabase를 사용할 때만 개발 프로젝트로 제한하며 비밀값을 저장소에 두지 않습니다.

## 2. 아이디에이션

- [ ] 대상 사용자와 해결할 문제가 구체적입니다.
- [ ] 선택한 해결 방향, 선택 이유, 하지 않을 일이 명확합니다.
- [ ] 성공 여부를 관찰 가능한 결과로 판단할 수 있습니다.

## 3. 플래닝 (Goal)

- [ ] Goal이 기능명이 아니라 사용자에게 생길 결과입니다.
- [ ] `Plan.md` 또는 GitHub Issue에 범위, 비범위, 제약이 있습니다.
- [ ] 구현 작업이 체크리스트이며 각 작업에 검증 방법이 있습니다.
- [ ] 완료 기준을 각각 참 또는 거짓으로 판정할 수 있습니다.

## 4. 검수

- [ ] 모든 변경이 Goal 범위 안에 있습니다.
- [ ] 코드 검사와 핵심 브라우저 흐름이 통과합니다.
- [ ] 콘솔 오류, 깨진 링크, 노출된 비밀값이 없습니다.
- [ ] 배포가 요청됐다면 production URL에서 다시 검증했습니다.

## 판정 원칙

명령 결과, 파일 경로 또는 URL이 있을 때만 `PASS`입니다. 확인하지 못한 항목은 `미확인`이며 `PASS`가 아닙니다.

에이전트는 Goal 범위 안의 안전한 `FAIL`을 개선하고 같은 검사를 반복한 뒤, 단계별 판정과 증거, 남은 문제만 보고합니다.
